# ADR-0028: تطبيق الويب القابل للتثبيت (PWA) — الحدود والاستراتيجية
الحالة: مقترح

## السياق
المتجر والإدارة وشاشة المندوب وPOS كلها «PWA» في الوثائق (ADR-0008، 0021، 0023) دون تفاصيل. قيود المتصفحات على الجوال (خاصة iOS) تحدد ما نعد به.

## القرارات المقترحة
1. **Manifest** لكل سطح بنطاق ومسار مستقل: `(store)` و`(admin)` و`(courier)` و`(pos)`؛ اسم وأيقونات وألوان، `display: standalone`، واتجاه RTL حسب اللغة.
2. **Service Worker أدنى:** غرضه **قابلية التثبيت وتخزين الملفات الثابتة** (JS/CSS/خطوط/أيقونات) فقط.
3. **ممنوع** تخزين استجابات API أو بيانات مالية/زبائن/طلبات في التخزين المؤقت للمتصفح. لا «عمل دون اتصال» للبيانات في الإصدارات الأولى (يتسق مع ADR-0008 وADR-0021). صفحة «لا يوجد اتصال» واضحة بدل ذلك.
4. **التحديث:** نسخة SW مربوطة بنسخة البناء، وتنبيه «تحديث متوفر» بدل التحديث الصامت الذي قد يكسر نموذجًا مفتوحًا.
5. **الكاميرا والباركود:** تتطلب HTTPS؛ المسح بـ`BarcodeDetector` حيث يتوفر وإلا مكتبة بديلة، والإدخال اليدوي دائمًا (ADR-0008).
6. **الإشعارات:** Web Push القياسي (مفاتيح VAPID) بلا Firebase؛ على iPhone تعمل فقط للتطبيق **المثبَّت على الشاشة الرئيسية** وبإصدارات نظام حديثة — **لم أتحقق من الإصدار الأدنى**. لذلك Push قناة اختيارية وليست الأساس (ADR-0025).
7. **Wake Lock** أثناء التوصيل النشط فقط (ADR-0018).
8. **تثبيت مدمج:** زر «ثبّت التطبيق» مرشَّد خاص بـiOS (تعليمات «إضافة إلى الشاشة الرئيسية») لأن iOS لا يعرض نافذة تثبيت تلقائية.
9. **الأمان:** نطاق SW محصور بسطحه؛ لا تخزين للتوكنات خارج الكوكيز `HttpOnly`.

## الخيارات المرفوضة
- «أوفلاين أولًا» بقاعدة محلية مزامَنة: خطر بيع مزدوج وتعارضات (ADR-0021)؛ يُقيَّم لاحقًا بعد التجربة.
- تطبيق أصلي الآن: مشروع إضافي (ADR-0008)؛ يُقيَّم إن أثبتت تجربة GPS والكاميرا قصورًا.

## المخاطر
اختلاف سلوك الكاميرا والإشعارات بين المتصفحات وأوضاع التثبيت (المستقل Standalone مقابل علامة تبويب): يُجرَّب على أجهزة حقيقية في 1A والمرحلة 9.

## ما لم يُختبر
كل شيء. اختبارات: التطبيق قابل للتثبيت (Lighthouse)، لا استجابة API في التخزين المؤقت (اختبار آلي)، تحديث SW لا يفقد نموذجًا مفتوحًا، صفحة عدم الاتصال تظهر. يدوي: تثبيت على أندرويد وiPhone.
