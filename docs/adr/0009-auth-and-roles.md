# ADR-0009: المصادقة والصلاحيات
الحالة: مقترح

## القرارات المقترحة
- **الموظفون والمناديب**: حسابات بهاتف/بريد وكلمة مرور (Argon2id أو bcrypt عبر مكتبة معتمدة)، جلسات بكوكيز `HttpOnly` + `Secure` + `SameSite`، حماية CSRF، وتحديد محاولات الدخول.
- **الزبائن**: **بدون حساب إجباري** (طلب كضيف بالهاتف)؛ التحقق عبر رد واتساب. حساب اختياري لاحقًا.
- **المكتبة**: Auth.js أو Better Auth — يُحسم في المرحلة 2 بعد تجربة سريعة (لا نكتب نظام مصادقة بأيدينا).
- **RBAC**: أدوار `owner, accountant, warehouse, courier` + صلاحيات دقيقة (مثال: `journal.post`, `order.confirm`, `courier.receive`)، تُفحص **على الخادم في كل عملية**.
- **سجل تدقيق** لكل عملية مالية وتغيير حالة وتغيير صلاحيات.
- 2FA للمالك والمحاسب (يُجدول لمرحلة التحصين).

## الخيارات المرفوضة
نظام مصادقة مكتوب يدويًا (خطر أمني)، وتسجيل إجباري للزبائن (يقلل التحويل).

## ما لم يُختبر
كل شيء. اختبارات الصلاحيات (رفض الوصول الأفقي والرأسي) شرط نجاح المرحلة 2.

---
## ملحق (15 نوفمبر): أدوار إضافية
`owner, manager, accountant, warehouse, cashier, courier` (+ مندوب شركة شحن لاحقًا عند الحاجة). **المدير** يؤكد تسليم النقد والتحويلات (ADR-0016). **الكاشير** لنقطة البيع فقط. الصلاحيات تُقيَّد بالفرع/المخزن (ADR-0015). **فصل الواجبات:** من يحصّل لا يؤكد تسليمه.
