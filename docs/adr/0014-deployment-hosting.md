# ADR-0014: الاستضافة والنشر — سحابي ومجاني
الحالة: مقترح — **يتأكد بتجربة جدوى في المرحلة 1 قبل الاعتماد**

## المتطلبات (من المالك)
نظام واحد سحابي: المتجر + لوحة التحكم + شاشة المندوب. استضافة وقاعدة بيانات **مجانيتان**. التجربة اليدوية من المالك على نسخة اختبار.

## ما تحققتُ منه (من مصادر منشورة 2026، وليس من تجربة فعلية)
- **Vercel Hobby (المجانية) تمنع الاستخدام التجاري** صراحة، والمتجر الذي يبيع تجاري. **لذلك لا نستخدمها لهذا المتجر.** (الخطة التجارية Pro مدفوعة.)
- **Cloudflare Workers** (الخطة المجانية) تسمح بالاستخدام التجاري، وتشغّل Next.js عبر المحوّل OpenNext. حدودها المنشورة صغيرة: نحو 100 ألف طلب يوميًا، وذاكرة 128 MB، وحجم برنامج مضغوط نحو 3 MB، وحد زمن معالج قصير لكل طلب (**تضاربت المصادر في رقمه**، فيُؤخذ من وثائق Cloudflare الرسمية). التوافق مع Next.js ليس كاملًا؛ المحوّل يوثّق فجوات.
- **Neon (PostgreSQL)** الخطة المجانية: نحو 0.5 GB، وتنام الحوسبة بعد 5 دقائق خمولًا (أول استعلام بعدها أبطأ)، بلا بطاقة، وفروع قاعدة بيانات (مفيدة لبيئة الاختبار).
- **Supabase** المجانية: 500 MB، وتتوقف المشاريع بعد أسبوع خمول، **بلا نسخ احتياطية** على الخطة المجانية.

## القرار المقترح (مكدس مجاني)
| الجزء | الاختيار | ملاحظة |
|---|---|---|
| التطبيق | Next.js على **Cloudflare Workers** (OpenNext) | HTTPS تلقائي (لازم لكاميرا المندوب) |
| قاعدة البيانات | **Neon Postgres** | فرع `main` للإنتاج، فرع `staging` للاختبار اليدوي |
| الصور | **Cloudflare R2** | يُتحقق هل يشترط حساب بطاقة |
| المهام الدورية | Cloudflare Cron Triggers (أو GitHub Actions المجدولة) | انظر ADR-0011: الصحة لا تعتمد عليها |
| النطاق | عنوان `*.workers.dev` المجاني أولًا | نطاق خاص مدفوع (سعر رمزي سنويًا) يُضاف عند الجاهزية |
| النسخ الاحتياطي | تصدير دوري مشفَّر إلى R2 | **ممنوع** حفظ نسخ القاعدة كـ Artifacts في مستودع عام (قابلة للتنزيل علنًا) |

## تجربة الجدوى (**أول عمل في المشروع كله — قبل اعتماد أي ADR**؛ المرحلة 1A)
تُنشر صفحة Next.js صغيرة على Workers تقرأ من Neon وتنفّذ حجزًا ذريًا تجريبيًا، ويُقاس: حجم الحزمة مقابل الحد، زمن الاستعلام البارد، نجاح معاملة الحجز، فتح الكاميرا على HTTPS، وتشغيل ORM. **إن فشل أي منها نتوقف ونسألك** (لا نغيّر الخطة وحدنا).

## البدائل إن فشلت التجربة (غير محققة)
- Cloudflare Workers Paid (نحو 5 دولارات شهريًا حسب مصدر منشور).
- جهاز افتراضي مجاني من مزوّد سحابي (مثل Oracle Always Free) بحاوية Docker: تحكم كامل لكن شروطه وتوفره **لم أتحقق منهما**، وقد يصعب التسجيل.

## العواقب والمخاطر
- **المجاني له سقف:** يصلح للإطلاق والتجربة، وعند نمو الطلبات (100 ألف طلب/يوم، 0.5 GB) سنقيس ونقرر معك متى تدفع. كل شاشة تصفح تستهلك طلبات (صور، ملفات)، فنستخدم التخزين المؤقت (cache) بقوة.
- نوم قاعدة Neon يبطّئ أول زائر بعد خمول.
- شروط الأسعار والحدود تتغير: تُراجع قبل الإطلاق.
- **سياسة:** لا تُفعَّل أي خدمة مدفوعة دون موافقتك.

## ما لم يُختبر
كل شيء أعلاه.

## ملحق (15 نوفمبر، مراجعة): مخاطر معروفة تُقاس في التجربة + خطة بديلة جاهزة
**مخاطر يجب أن تجيب عنها التجربة بأرقام (لم أتحقق منها؛ كلها حسب علمي وقد تكون قديمة):**
1. حد **زمن المعالج لكل طلب** في الخطة المجانية (قد يكون عشرات الملّي ثانية فقط) — هل يكفي صفحة تقرير أو إتمام طلب؟
2. حد **حجم الحزمة المضغوطة** (نحو 3MB على المجانية) — هل يتسع تطبيق واحد فيه المتجر والإدارة وPOS والرسوم وORM وi18n؟
3. حد **عدد الطلبات الفرعية** لكل طلب (استعلامات HTTP لـNeon قد تُحسب منها).
4. **المعاملات**: سائق HTTP لا يناسب المعاملات التفاعلية ⇒ لذلك العمليات الحرجة دوال PostgreSQL (ADR-0003).
5. شرط بطاقة لـR2، وحدود Cron، وزمن الاستيقاظ البارد لـNeon.

**معايير النجاح الرقمية المقترحة للتجربة (تُعتمد معك):** إتمام طلب بسطرين (حجز + Outbox) خلال زمن نتفق عليه؛ 50 حجزًا متزامنًا على كمية 5 ينجح 5 فقط؛ حجم الحزمة أقل من الحد بهامش لا يقل عن 30%.

**خطة بديلة جاهزة (تُفعَّل فقط بموافقتك إن فشلت التجربة):**
- **ب1:** فصل التطبيق إلى Worker للمتجر (خفيف) وWorker/مضيف مستقل للإدارة وPOS.
- **ب2:** حاوية Node واحدة على مزوّد استضافة منخفض التكلفة أو طبقة مجانية مؤهلة تجاريًا (**لم أتحقق من أي مزوّد**)، مع Neon كما هو.
- **ب3:** Workers Paid (تكلفة صغيرة؛ يحتاج موافقتك — لا نفعّل مدفوعًا وحدنا).
