# ADR-0017: أنماط التوصيل وشركات الشحن
الحالة: مقترح

## قرار المالك
- التوصيل قد يتحمل رسومه **الشركة** وقد يتحملها **الزبون**، ويُحدَّد داخليًا (بحسب فهمي لعبارتك — **يُرجى التأكيد**).
- «شركات الشحن بإمكاني التعامل معها أيضًا».

## القرارات المقترحة
واجهة `DeliveryProvider` بثلاثة أنماط، يُختار النمط لكل طلب:
1. **مندوب داخلي** (شاشة المندوب، ADR-0008).
2. **شركة شحن خارجية:** تُسجَّل الشركة ورقم التتبع وتكلفة الشحن وحالة التسليم **يدويًا أولًا**؛ وتسوية نقد الشركة (COD) كذمة على الشركة تُسدَّد بتحويلها. ربط API لشركة محددة لاحقًا بمحوّل مستقل (لا نعرف الشركة ولا واجهتها بعد).
3. **استلام من المحل** (بلا توصيل).

**رسوم التوصيل:** قاعدة لكل طلب: `يدفعها الزبون` (تُضاف للإجمالي، وتُسجَّل إيراد توصيل أو استرداد تكلفة) أو `تتحملها الشركة` (مصروف توصيل)، مع جدول رسوم بحسب المنطقة. **عمولة المندوب:** ثابتة أو نسبة (سؤال معلّق) وتُسجَّل مصروفًا.

## المخاطر
اختلاف شركات الشحن في الحالات والتسوية: لذلك محوّل لكل شركة بعد معرفتها.

## ما لم يُختبر
كل شيء. اختبارات المرحلة 17: تسوية COD، فشل التوصيل مع شركة، رسوم بالمنطقة، ومن يتحمل الرسوم يؤثر صح على القيود.

---
## ملحق v5 (تكامل المبيعات — ADR-0032)
1. **`delivery_attempt`:** سجل إضافة-فقط لكل محاولة (مندوب/شركة، نتيجة، سبب، رقم تتبع، تكلفة)؛ `delivery` تصير ملخصًا 1:1 مع الطلب. تسمح بإعادة المحاولة بمندوب آخر.
2. **الشحن بشركة:** R4 تدين **1100 ذمم الشحن** لا 1150؛ التسوية بقاعدة R-carrier وجدول `carrier_settlement` (المرحلة 17، الإصدار 2).
3. **رسوم توصيل تتحملها الشركة:** قاعدة R-fee (6030) محدَّدة الآن بدل ترك الحالة بلا قاعدة.
4. **عمولة المندوب:** جدول `courier_commission` واستحقاق/سداد/عكس (سؤال PRD 6 و30).
**لم يُختبر.**
